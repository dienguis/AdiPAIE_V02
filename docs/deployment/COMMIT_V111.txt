1. NOUVEAU : Action "Rattraper acquisitions" (plage de mois)
================================================================================

Cas d'usage metier : bascule vers SunuPaie en cours d'annee.
Les salaries n'ont jamais recu les acquisitions mensuelles automatiques des
mois precedant la bascule. Resultat : les soldes sont a 0 (ou negatifs si des
conges ont ete pris et saisis manuellement).

L'action "Acquis. mensuelle" existante ne traite que le mois courant (idempotent).
Pour un salarie vierge en octobre, elle credite seulement +2j au lieu des +20j
cumules depuis janvier.

Solution : nouveau bouton "Rattraper acquisitions" sur ListView SoldeConge.
Popup demande la plage (Mois/Annee debut + Mois/Annee fin). L'action boucle
mois par mois et appelle AcquerirTousSalaries pour chaque, de maniere idempotente.

Resultat teste en local (13/10/2026) :
  - Avant : diop Modou solde = -24,00 (0 acquis, 24 pris)
  - Rattrapage janvier a septembre 2026 (9 mois)
  - Apres : diop Modou solde = -6,00 (18 acquis, 24 pris)
  - Fatou NDIAYE solde = +18,00 (nouvelle beneficiaire)
  - Total : 18 acquisitions creees, 0 ignorees, 0 erreur

Rapport detaille mois par mois dans le message de confirmation
(ex. "01/2026 : 2 cree(s), 0 ignore(s)...").

Fichiers crees :
  - AdiPAIE_V02.Module/NonPersistent/RattraperAcquisitionsRequest.cs (DTO popup)

Fichiers modifies :
  - AdiPAIE_V02.Module/Controllers/SoldeCongeController.cs
    (ajout PopupWindowShowAction dans AcquisitionMensuelleController)
  - AdiPAIE_V02.Module/Module.cs
    (enregistrement du DTO dans AdditionalExportedTypes)

Idempotent : relancer l'action deux fois sur la meme plage ne cree rien de nouveau
(AcquerirMensuel verifie la presence d'un MouvementSolde AcquisitionMensuelle
sur le mois en cours).

2. FIX V1.10.2 : Permissions SoldeConge/MouvementSolde pour le role RH
================================================================================

Bug : le role RH n'avait aucune permission sur SoldeConge ni MouvementSolde.
Resultat : le menu "GRH -> Soldes de conges (operationnel RH)" etait invisible
pour le RH et le bouton "Acquis. mensuelle" inaccessible.

Cause racine : lors de la mise en place du strict DenyAllByDefault, seule la
permission AddType<SoldeConge>(dg, "r") avait ete declaree, oubli pour le role RH.

Correctif : ajout dans InitialiserRolesGRHController :
  - SoldeConge      rwcd  (consultation + corrections manuelles)
  - MouvementSolde  rwcd  (tracage + correction des mouvements)
  - CongeType       rw    (edition des parametres par type de conge)

Post-deploiement : clic sur "Init. roles GRH" dans l'app + deconnexion/reconnexion
du user RH.
