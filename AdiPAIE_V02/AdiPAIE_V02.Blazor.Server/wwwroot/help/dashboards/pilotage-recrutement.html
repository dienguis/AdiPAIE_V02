Tableau N°12 · V1.4

Pilotage Recrutement

Vue 360° du processus de recrutement ELTON : postes ouverts, pipeline candidatures, performance des sources, délai moyen, coût par embauche, périodes d'essai en cours. Permet à la DRH et au manager hiérarchique de piloter chaque étape du tunnel d'acquisition de talents.

À quoi sert ce tableau

Avant V1.4, le suivi du recrutement se faisait via un fichier Excel partagé. Ce dashboard centralise toutes les candidatures dans la base XAF avec un workflow de pipeline réaliste (Reçue → Pré-sélection → Entretien planifié → Entretien fait → Offre proposée → Offre acceptée → Embauché). Il fournit les indicateurs RH classiques (coût d'acquisition, délai moyen, taux de conversion) et un suivi des périodes d'essai post-embauche.

Pour qui

  • DRH : pilotage global du recrutement, validation budgets, négociation avec sociétés de chasse de têtes.
  • Responsable recrutement / Talent Acquisition : suivi quotidien du pipeline, identification des goulots d'étranglement.
  • Managers hiérarchiques : visibilité sur les postes ouverts dans leur périmètre + statut des candidats.
  • DAF : suivi du coût par embauche pour budget annuel.

Prérequis : alimenter les données

Avant de voir des KPIs, il faut alimenter les entités du module Recrutement (groupe menu GRH - Recrutement) :

  1. Référentiels à créer une seule fois :
    • Motif d'ouverture poste (Croissance, Remplacement, Création de fonction)
    • Source de recrutement avec le coût moyen par candidat (LinkedIn, Recommandation, ANEM, Salons emploi…)
    • Motif refus candidat (côté entreprise : manque expérience, prétentions trop élevées…)
    • Motif refus offre (côté candidat : rémunération insuffisante, autre offre…)
  2. Poste vacant : créer une fiche dès qu'un poste est ouvert. Statut Brouillon → Validé DRH → Publié → En recrutement → Pourvu.
  3. Candidat : 1 fiche par personne, multi-candidatures possibles.
  4. Candidature : association Candidat × Poste avec statut workflow.
  5. Entretien : créer un entretien dès qu'il est planifié, mettre la note + l'avis après l'entretien.
  6. Offre d'emploi : créer dès qu'on prépare une proposition formelle.
  7. Période d'essai : créer à l'embauche pour suivre les 3 mois standards (CCT Sénégal).

Sections du tableau

Pipeline de recrutement (funnel)

7 barres horizontales qui visualisent le tunnel d'acquisition. Pour chaque étape (Reçue, Pré-sélection, Entretien planifié, Entretien fait, Offre proposée, Offre acceptée, Embauché), on calcule le nombre de candidatures qui ont atteint cette étape (statut numérique ≥ seuil). Le pourcentage indique :

  • vs total reçu : largeur visuelle de la barre (% du total reçu).
  • ↓ vs étape précédente : à droite, taux de passage entre 2 étapes consécutives. Permet d'identifier les étapes où on perd le plus de monde (souvent : passage entretien → offre).

Évolution mensuelle

Pour chaque mois de l'année cible, 3 colonnes : nb postes ouverts (DateOuverture sur ce mois), nb candidatures reçues (DateSoumission sur ce mois), nb embauches (DateDecision + statut Embauché sur ce mois). Permet de détecter les saisonnalités (rentrée, fin d'année…).

Performance des sources de recrutement

Pour chaque source (LinkedIn, ANEM…) : nb candidatures, nb entretiens, nb embauches, taux de conversion, coût moyen par candidat (saisi sur le référentiel), coût total et coût par embauche. C'est le KPI le plus stratégique : il permet de réallouer le budget vers les sources les plus efficaces.

Délai recrutement par catégorie

Décomposition du délai moyen par catégorie professionnelle (Cadres, Maîtrise, Employés…). Affiche aussi min et max pour identifier les catégories où certains recrutements traînent anormalement.

★ Liste des postes ouverts (priorisée)

Tableau trié par Jours d'ouverture décroissant. Les lignes avec plus de 60 jours d'ouverture sont surlignées en orange (alerte : poste qui traîne, à investiguer). Affiche pour chaque poste : code, libellé, département, site, catégorie, type contrat, statut, date ouverture, jours, nb candidatures reçues, nb entretiens menés.

Périodes d'essai en cours

Pour chaque salarié en période d'essai : nom, poste, site, date début, date fin prévue, jours écoulés, jours restants. Les lignes avec ≤ 7 jours restants sont surlignées en orange (le manager doit prendre sa décision dans la semaine).

Motifs de refus

2 tables côte à côte :

  • Côté entreprise : pourquoi ELTON refuse certains candidats (analysés sur Candidature au statut Refusé).
  • Côté candidat : pourquoi des candidats refusent les offres ELTON (analysés sur OffreEmploi au statut Refusée candidat). Indicateur clé pour ajuster la politique salariale.

Filtres disponibles

  • Année : par défaut année en cours.
  • Type de contrat : Tous, CDI, CDD, Stage.
  • Sites : multi-sélection (chips). Filtre les postes selon leur Site.
  • Catégories professionnelles : multi-sélection (chips).

Le bouton Actualiser (en haut à droite) invalide le cache (TTL 5 min) et recalcule les données depuis la base.

Bonnes pratiques

  • Saisir le coût par source : le calcul du coût total recrutement n'a de sens que si chaque référentiel SourceRecrutement a son CoutMoyenParCandidat renseigné (ex. LinkedIn ≈ 25 000 FCFA / cand., ANEM ≈ 0 FCFA, Salon emploi ≈ 40 000 FCFA).
  • Workflow strict : faire passer la candidature par chaque étape (ne pas sauter de Reçue à Embauché) pour que le funnel soit fiable.
  • Renseigner le motif de refus : sans cette info, l'analyse stratégique est inopérante.
  • Lier l'embauche à la fiche Salarié : sur Candidature au statut Embauché, renseigner le champ Salarié créé (FK vers la fiche Salarié). Crée une PeriodeEssai liée pour le suivi 3 mois.

Données démo

Le seeder créé automatiquement (Updater) crée 5 postes (2 pourvus + 2 en recrutement + 1 brouillon), 30 candidats, ~50 candidatures avec workflow réaliste, 20 entretiens, 8 offres d'emploi (issues variées) et 2 périodes d'essai en cours. Tous préfixés DEMO_RECRUT_ / DEMO_CAND_ / DEMO_POSTE_ et supprimables via le Controller Vider données démo.

Limites connues

  • Le coût par source est un coût par candidat entré, pas par embauche réussie. Pour avoir un coût par embauche, le dashboard divise le coût total par le nombre d'embauches (ce qui pénalise les sources avec beaucoup de candidatures non retenues).
  • Le délai recrutement est calculé sur DateOuverture du poste — il ne distingue pas le temps de validation interne (Brouillon → Validé) du temps de sourcing actif.
  • Pas (encore) d'export Excel/PDF du dashboard. Roadmap V1.4.1.
