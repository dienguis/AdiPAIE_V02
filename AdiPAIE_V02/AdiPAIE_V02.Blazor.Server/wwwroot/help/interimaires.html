👷 Module Intérimaires — Guide complet

💼 Cas d'usage concrets ELTON

Cas 1 — Remplacement saisonnier en Boutique

  1. Manager BANDIA crée demande : 2 caissiers pour juillet-août
  2. RH valide → DAF valide budget → Approuvée
  3. RH sélectionne 2 intérimaires de la base (statut Disponible)
  4. Création de 2 contrats : Site = BANDIA, Unité = Boutique, durée 2 mois
  5. En septembre : statut contrats = Terminé automatiquement à DateFin
  6. Tableau N°3 Mouvements montre les 2 arrivées juillet + 2 départs août

Cas 2 — Renfort pluri-segments à la Direction Commerciale

  1. DG demande renfort pour le projet « Boost BTP-Mines » sur 6 mois
  2. Création contrat : Site = Siège ELTON, Unités = Segment BTP + Segment Mines (multi)
  3. Le coût apparaîtra dans le tableau Rémunération sous Siège ELTON, et dans la décomposition par Unité sur les 2 segments

Cas 3 — Mutation Station → Dépôt

  1. Intérimaire MERMOZ (Pompiste) muté au Dépôt Dakar (Magasinier) en cours de contrat
  2. Créer un Mouvement : Origine MERMOZ/Piste → Destination Dépôt Dakar
  3. Le contrat ne change pas de Site automatiquement — il faut éditer le contrat manuellement pour le réaffecter
  4. Tableau Mouvements affichera ce mouvement

❓ FAQ et erreurs fréquentes

Q : Pourquoi mon contrat n'apparaît pas dans les dashboards EXTERNE ?

Cause probable : le champ Site (V1.1) n'est pas renseigné. Les dashboards V1.1 lisent uniquement ContratInterim.Site + ContratInterim.Unites. Si vous avez rempli les anciens champs [Legacy] Station / [Legacy] BU, ils ne sont plus utilisés par les dashboards.

Fix : ouvrir le contrat → renseigner Site + Unités → Save → recharger le dashboard.

Q : J'ai créé une nouvelle BU (ex: « Restauration ») mais elle n'apparaît pas dans Unités

Vérifier que :
- L'unité est bien rattachée à un Site (FK obligatoire)
- L'unité est Active (case à cocher)
- Le Type d'unité est cohérent (BU pour station, Département pour siège)

Q : Le % Renouvellement dépasse 100 % sur un site

C'est normal en V1.1 si beaucoup de contrats courts se succèdent sur peu de places. Ex: 11 contrats de 1 mois sur 3 places dans l'année = 366 % de renouvellement « rotatif ».

Depuis le fix Sprint 1C.2 fix2, le ratio est plafonné à 100 % naturellement (numérateur et dénominateur en contrats). Si vous voyez encore > 100 %, rafraîchissez le cache via le bouton ↻ Refresh du dashboard.

Q : Comment savoir qui a accès au module Intérimaires ?

Les rôles autorisés sont définis dans Updater.cs :

🧪 Données démo pour tester

Au premier démarrage de l'application, un seed crée automatiquement un jeu de données démo (préfixe DEMO_) pour permettre la formation et les tests :

  • 6 sites : 3 stations (BANDIA, CAP DES BICHES, MERMOZ) + 1 Siège + 2 Dépôts (Dakar, Thiès)
  • 19 unités : 12 BU station + 4 départements siège + 3 segments commerciaux
  • 1 société d'intérim : DEMO_SEN-INTERIM
  • 8 postes : Caissier, Pompiste, Laveur, Technicien, Chef Boutique, Magasinier, Comptable Aux., Assistant RH
  • 25 intérimaires : noms sénégalais réalistes (DIOP, SARR, FALL…)
  • ~40 contrats répartis 2024-2026 sur tous les sites
  • 10 mouvements entre sites

Désactiver le seed démo en production

Modifier appsettings.json : 
"Dashboards": {
    "SeedDemoData": false
}
OU positionner la variable d'environnement : 
set DASHBOARDS_SEED_DEMO=false

Supprimer toutes les données démo

Aller dans Administration → Mon profil utilisateur (Admin) → bouton Vider les données démo → confirmer.

Ce bouton supprime UNIQUEMENT les enregistrements préfixés DEMO_. Vos données métier réelles (rubriques de paie, paramètres, catégories, etc.) ne sont JAMAIS touchées car leurs codes ne commencent pas par DEMO_.
