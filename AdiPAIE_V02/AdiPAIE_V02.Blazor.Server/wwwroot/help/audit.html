Journal d'audit - Guide Admin

Le journal d'audit assure la tracabilite des actions sensibles effectuees dans SunuPaie : validations de bulletins, cloture de periodes, workflows RH, sanctions disciplinaires, imports de donnees. Chaque entree enregistre qui a fait quoi, quand, sur quel objet. Les entrees sont en lecture seule : elles ne peuvent etre ni modifiees ni supprimees. Ce guide s'adresse a l'administrateur et au RH responsable du controle interne.

1. Vue d'ensemble : ce qui est trace

Le flux d'enregistrement

Action metier
(validation, cloture...)
›
AuditService.Enregistrer
›
AuditEntry persistee
(ObjectSpace separe)
›
Consultation RH / Admin
(lecture seule)
L'ecriture d'audit utilise un ObjectSpace separe de la transaction metier. Si l'ecriture audit echoue, l'action metier aboutit quand meme : le metier prime sur la trace. A l'inverse, aucune action metier n'est bloquee par le journal.

Modules et actions tracees

ModuleActions tracees
Bulletins de paieValider, Cloturer, Rouvrir
Periodes de paieOuvrir, Cloturer, Reouverture forcee (admin)
Offboarding (STC)Calculer le solde, Valider RH, Valider DAF, Cloturer
DisciplinaireNotifier, Programmer audition, Enregistrer audition, Prononcer sanction, Cloturer
CongesAcquisition mensuelle, Report N vers N+1, Rattrapage historique
ImportsImport salaries, conjoints, comptes bancaires (compteurs crees / ignores / erreurs)
Non trace : les consultations simples (ouverture d'une liste, affichage d'une fiche) ne sont pas enregistrees. Seules les actions qui modifient un etat metier remontent dans le journal.

Champs enregistres par entree

DateAction
Date et heure exacte de l'action (ex. 14/10/2026 09:32). Indexee pour les filtrages par plage.
Utilisateur
Nom de l'utilisateur connecte au moment de l'action. Si l'action est declenchee par le systeme (batch planifie), la valeur est "(systeme)".
NomEntite
Type d'objet concerne (Bulletin, PeriodePaie, DossierOffboarding, DossierDisciplinaire, SoldeConge...).
Action
Libelle de l'operation effectuee (Valider, Cloturer, Prononcer sanction, Rattrapage acquisitions...).
ObjectId / ObjectLabel
Identifiant technique (Oid) et libelle lisible de l'objet concerne (ex. "DIOP Moussa - 04/2026").
Details
Texte libre apportant du contexte (montants, compteurs, parametres saisis). Champ non limite en taille.
AncienStatut / NouveauStatut
Pour les transitions d'etat : la valeur avant et apres l'action. Ex. "Brouillon" vers "Valide".
AdresseIP
Adresse IP du poste a l'origine de l'action, lorsque disponible.

2. Consulter le journal

2.1Ouvrir la liste

Menu : Administration › Journal d'audit

La liste affiche toutes les entrees, triees par defaut sur DateAction descendant (les plus recentes en premier). Les colonnes visibles sont Date, Utilisateur, Entite, Action, Libelle objet.

Acces reserve aux roles Administrators et RH_Manager. Les autres roles n'ont ni le menu ni la permission de lecture sur AuditEntry.

2.2Ouvrir le detail d'une entree

Double-clic sur une ligne. La vue detail affiche :

  • Les champs de la liste (Date, Utilisateur, Entite, Action, Libelle)
  • Details modifications : contexte complet
  • Ancien statut et Nouveau statut
  • Adresse IP du poste a l'origine de l'action

Tous les champs sont en lecture seule. Aucun bouton d'edition ni de suppression n'est propose.

3. Rechercher et filtrer

3.1Filtres de colonne

Cliquer sur l'entete d'une colonne pour appliquer un filtre :

  • Utilisateur : saisir ou choisir un nom pour voir toutes ses actions
  • Entite : limiter a un type d'objet (Bulletin, DossierOffboarding...)
  • Action : limiter a une operation precise (Valider, Cloturer...)
  • Date : filtre de type plage (entre deux dates)
  • Libelle objet : recherche partielle sur le nom (ex. "DIOP" ou "04/2026")

3.2Cas d'usage frequents

Qui a valide ce bulletin ?

Filtrer : Entite = Bulletin, Action = Valider, Libelle objet contient le nom du salarie et le mois.

Historique complet d'un dossier de depart

Filtrer : Entite = DossierOffboarding, Libelle objet contient le nom du salarie. Toutes les etapes du workflow apparaissent avec leurs horodatages (calcul STC, validation RH, validation DAF, cloture).

Sanctions prononcees sur une periode

Filtrer : Entite = DossierDisciplinaire, Action = Prononcer sanction, Date entre les deux bornes voulues.

Verifier qu'aucune reouverture forcee n'a eu lieu

Filtrer : Action = Reouverture forcee. Toute entree correspondante doit etre justifiee par un ticket ou une note RH.

Tracer un import de salaries

Filtrer : Entite = Import, Action contient Import salaries. Le champ Details liste les compteurs (crees, ignores, erreurs) et le nom du fichier source.

3.3Vue d'ensemble d'un utilisateur

Pour auditer l'activite d'un compte sur une periode donnee, combiner Utilisateur et Date. Trier par Date croissant pour obtenir la chronologie exacte des actions sensibles effectuees.

4. Export et archivage

4.1Export Excel

Depuis la liste filtree, utiliser l'action standard Export de la barre d'outils XAF (format XLSX, CSV ou PDF). L'export respecte le filtre courant et l'ordre d'affichage.

Pour un controle externe (commissaire aux comptes, audit social), prevoir :

  • Un export filtre par plage de dates (exercice ou trimestre)
  • Un second export filtre sur les actions sensibles uniquement (Valider, Cloturer, Reouverture forcee, Prononcer sanction)
  • Archivage du fichier dans le dossier conformite de l'entreprise

4.2Retention

Il n'y a pas de purge automatique : les entrees d'audit sont conservees indefiniment dans la base. Si le volume devient important apres plusieurs exercices, prevoir avec l'equipe technique une procedure d'archivage hors-base (export annuel puis suppression ciblee par script SQL).

Imperatif : toute suppression de donnees d'audit doit etre tracee elle-meme (ticket, note de l'admin DBA, export prealable complet). Ne jamais purger via l'interface : la table est en lecture seule pour tous les roles applicatifs.

5. Depannage et FAQ

Je ne vois pas le menu "Journal d'audit"

Le role de l'utilisateur n'a pas la permission de lecture sur AuditEntry. Reserve a Administrators et RH_Manager. Faire reinitialiser le role via Parametres de paie › Init. roles GRH puis deconnexion/reconnexion.

Je ne retrouve pas une action que j'ai faite

Verifier d'abord qu'il s'agit bien d'une action tracee (cf. section 1, tableau des modules). Les consultations simples et les modifications de champs non sensibles ne remontent pas dans le journal. Verifier aussi le filtre courant : un filtre residuel sur Utilisateur ou Date peut masquer la ligne.

Le champ Utilisateur affiche "(systeme)"

L'action a ete declenchee par un batch ou un traitement automatique en dehors d'une session utilisateur (ex. job planifie). Comportement normal. Le champ Details precise le contexte.

Deux entrees identiques a la meme seconde

Cas possible si une action metier a declenche deux evenements audit (ex. validation en cascade). Comparer les champs Details et ObjectId pour identifier les objets concernes : il s'agit en general de deux objets distincts traites dans la meme transaction.

Peut-on modifier une entree erronee ?

Non. Les entrees sont strictement en lecture seule. Si une action metier erronee a ete tracee, elle reste dans le journal. L'approche correcte consiste a effectuer l'action corrective en metier (qui generera a son tour une entree d'audit) et a documenter la correction dans un ticket ou une note RH.
