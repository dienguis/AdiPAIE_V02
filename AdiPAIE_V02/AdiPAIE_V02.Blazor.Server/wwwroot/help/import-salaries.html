📥 Import en masse des salariés — Guide complet

Cette fonctionnalité permet d'importer plusieurs salariés en une seule opération à partir d'un fichier Excel (.xlsx). Idéal pour la migration initiale depuis un ancien SIRH ou l'intégration en lot de nouveaux effectifs. Le processus est idempotent : les matricules existants sont ignorés.

📥 Modèle (.xlsx)

📥 Étape 1 — Télécharger le modèle

1Aller dans la liste Salariés

Cliquer sur 📥 Télécharger modèle import dans la barre d'actions.

2Sauvegarder le fichier

Le fichier Modele_Import_Salaries.xlsx est téléchargé avec les en-têtes pré-formatés et une ligne d'exemple en italique gris.

✏️ Étape 2 — Préparer le fichier Excel

1Ouvrir avec Excel ou LibreOffice

2Supprimer la ligne d'exemple (ligne 2)

3Remplir vos données

Une ligne = un salarié. Renseigner au minimum les colonnes obligatoires : Matricule, Nom, Prénom.

4Enregistrer au format .xlsx

Les formats .xls, .csv, .ods ne sont pas supportés.

📤 Étape 3 — Importer dans SunuPaie

1Cliquer sur Importer depuis Excel

Bouton dans la barre d'actions de la liste Salariés.

2Sélectionner votre fichier

Cliquer sur le champ fichier dans le popup.

3Cliquer sur Importer

Le traitement démarre (typiquement quelques secondes pour 100 lignes).

📊 Étape 4 — Vérifier le rapport et compléter

1Lire le rapport de fin

Format : "X créé(s), Y ignoré(s), Z erreur(s)". La liste est rafraîchie automatiquement.

2Compléter les fiches créées

Ajouter les éléments non couverts par l'import : conjoints, comptes bancaires, pièces d'identité, photo, affectations multiples si applicable.

📜 Règles de traitement

  • Matricule unique : si déjà en base, ligne ignorée (pas de doublons, pas de mise à jour).
  • Nom + Prénom obligatoires : sinon ligne en erreur.
  • Échelon prioritaire : si Échelon renseigné et valide, SB/Logt/Catégorie/Convention auto-alignés. Les colonnes SalaireBase/Logement sont ignorées.
  • Sexe ↔ Civilité : M → Monsieur, F → Madame.
  • Véhicule : si PossedeVehicule = Oui, PrimeTransport mise à 0.
  • Departement / Fonction : doivent exister exactement (casse ignorée). Sinon champ laissé vide.
  • DateEmbauche par défaut : date du jour si vide.
  • Traçabilité : chaque import est tracé dans le journal d'audit (compteurs créés/ignorés/erreurs).

Pré-requis avant import

Avant d'importer, créer si nécessaire :
  • Les échelons, catégories, conventions (si classification conventionnelle utilisée)
  • Les départements et fonctions (sinon les champs seront vides)

🎯 Cas d'usage concrets

Cas 1 — Migration initiale (200 salariés)

Lors du démarrage SunuPaie, le RH prépare un fichier de 200 lignes depuis l'export du SIRH précédent. Import en une opération : 198 créés, 2 erreurs (matricule vide). Correction manuelle des 2 lignes restantes.

Cas 2 — Import partiel par échelon

Le RH importe 15 nouveaux chefs de station avec uniquement Matricule, Nom, Prénom, DateEmbauche, Echelon = E2-A. Le système complète automatiquement SB, Logt, Catégorie depuis l'échelon.

Cas 3 — Import idempotent (réessais)

Le RH lance l'import deux fois par erreur. Résultat de la 2e : 0 créés, 200 ignorés, 0 erreurs. Aucun doublon créé, aucun risque de corruption.

❓ FAQ et erreurs fréquentes

"Colonne 'Matricule' introuvable" → Vérifier l'orthographe exacte de l'en-tête en ligne 1 : Matricule.
"Fichier Excel vide ou introuvable" → Le fichier uploadé est vide ou corrompu. Ré-enregistrer puis réessayer.
"Ligne X : matricule vide — ignoré" → Renseigner un matricule unique pour chaque salarié.
"Ligne X : SAL001 existe déjà — ignoré" → Normal, le système évite les doublons (idempotent).
💡 Exemple complet : 4 lignes (SAL001, SAL002, SAL003, SAL001 doublon) → résultat 3 créés, 1 ignoré, 0 erreur. SAL001 et SAL003 ont un échelon (alignement auto), SAL002 a un SB manuel.
